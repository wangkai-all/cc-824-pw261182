# 混池策略分析系统（Pooling Strategy Analysis）

一个从零构建、**零运行时依赖**的混池（pooled testing）策略分析与合成演练系统。所有样品、
风险参数、检测性能与实验结果均为**虚构数据**，用于方法演示，不对应任何真实样品或患者。

## 它解决什么问题

先把样品**混池检测**，再对阳性池**拆检**以节省费用；但混池会带来**稀释**（灵敏度随池大小下降）
与**污染**（特异性下降、误判上升）。本系统在以下约束下联合决定「怎么分池」与「阳性后怎么拆」：

- 同批样品风险**可能相关**（潜在共同来源事件），**不使用独立同分布（i.i.d.）的固定公式**；
- 检测灵敏度/特异性**随池大小变化**；
- 策略**只依据已得到的池结果**分支，绝不偷看虚构真值；
- 每次检测从原样品扣除等分样，**重复拆检不能无限用样**，样量不足即退出候选；
- 同时给出**费用最小**与**漏检受限**两类目标，并在风险假设缺乏证据时给出**敏感性区间**；
- **不宣称保证发现全部异常样品**。

## 快速开始

需要 Node.js ≥ 20（纯 ESM，无第三方依赖）。

```bash
npm test            # 31 个引擎单元/集成测试
npm run demo        # 命令行端到端演示
npm run serve       # 启动静态服务器，浏览器打开 http://127.0.0.1:8240/web/
```

## 网页演练台（`web/`）

四个功能页，所有分析都直接调用 `src/` 引擎，前端只负责交互与渲染：

1. **分池演练台** — 可拖动（或点选）把样品分入各池，实时显示池容量与检测费；查看引擎的
   「下一步」推荐与候选方案代价；勾选污染轮后**执行一轮合成检测**；查看每个样品的**剩余样量**。
2. **后验与检测性能** — 台账贝叶斯更新后的样品阳性后验、潜在事件后验，以及 Se(k)/Sp(k) 随池
   大小变化曲线；每张图都配数据表与悬停提示。
3. **冻结方案 · 整批评估** — 冻结当前参数后做蒙特卡洛重演，对比费用最小 vs 漏检受限；附
   N=4 小样本精确枚举核对，与 9 情景敏感性区间。
4. **检测台账** — 只追加的事件流；支持把任一结果**更正**（追加 CORRECTION，不抹除原始记录），
   并显示污染事件、费用与台账自检结果。

> 必须通过 `npm run serve`（HTTP）访问，不要用 `file://` 直接打开——浏览器的 ESM 导入需要 HTTP。

## 目录结构

```
src/            分析引擎（纯函数，可被 Node 与浏览器共用）
  risk-model.mjs   相关风险模型：潜在事件 + 个体真值的联合分布、联合状态枚举、敏感性情景
  assay.mjs        池大小依赖的灵敏度/特异性、合成检测抽样、费用与样量口径
  ledger.mjs       只追加台账：检测/污染/更正事件、样量扣减、容量校验、自检
  inference.mjs    联合状态上的精确贝叶斯后验 / 粒子（SIS）后验
  policy.mjs       一步前瞻推荐、两阶段方案评估、N≤6 约束动态规划精确核对
  simulation.mjs   自适应批次蒙特卡洛、两策略对比、敏感性分析
  rng.mjs          可复现的种子随机数（mulberry32）
data/           虚构演示批次（N=10 主批次、N=4 小样本核对批次）与参数模板
web/            演练台前端（index.html / styles.css / app.mjs / charts.mjs）
tools/serve.mjs 零依赖静态文件服务器
tests/          node:test 测试与命令行演示
docs/           方法假设、口径与边界说明
```

## 两类目标

- **费用最小（cost-min）**：最小化 `期望检测费 + λ·期望漏检数`，λ 为漏检一个阳性的折算代价。
- **漏检受限（miss-bound）**：在 `期望漏检数 ≤ 约束` 的策略中选期望检测费最低者。
  小样本用约束动态规划求精确受限树；大样本用更高 λ 的启发式，并由蒙特卡洛评估实际表现。

## 重要边界

检测灵敏度恒小于 1，且样量有限，因此**任何方案都存在漏检可能**。系统输出的是给定假设下的
期望与区间，不是对「找到全部阳性」的承诺。参数缺乏证据时，请以 `docs/methodology.md` 描述的
敏感性区间为准。
